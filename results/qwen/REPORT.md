# Qwen3.8-Flash-Next 측정 결과

측정 기간: 2026-09-27 (Asia/Seoul)

이 보고서는 두 대의 DGX Spark에서 진행한 Qwen3.8-Flash-Next 회귀 측정의 공개용 집계입니다. 하드웨어와 GPU 클럭 기록의 범위는 [실험 환경](../../README.md#실험-장비와-구성)을 참고하십시오. 원시 응답, 요청 payload, endpoint 설정, 내부 네트워크 주소, 호스트·컨테이너 식별자는 포함하지 않습니다.

## 8K 품질 비교

Core60 중 장문 8개를 제외한 52개 문항을 각 3회 실행했습니다. Coding/Reasoning 출력 한도는 8,192 토큰, 나머지 단일 요청은 4,096 토큰이며, temperature 0.6, top-p 0.95, top-k 20, Thinking ON, client concurrency 1을 사용했습니다. 잘린 응답은 실패로 계산했습니다.

| 역할 | 체크포인트 revision | 서빙 설정 |
|---|---|---|
| NVIDIA NVFP4 기준 | `fc694b54fb0174e0913e6adf86691ef85a4ead47` | vLLM 0.30.0, MTP2, `max_num_seqs=4`, BF16 KV |
| hibrid48 | `e316057ddc794cbf76c3ef28bfd1c7b62b20128c` | vLLM 0.30.0, MTP5, `max_num_seqs=64`, BF16 KV |

| 영역 | 고유 문항 | NVIDIA NVFP4 기준 실행 | hibrid48 실행 | 통과율 차이 (hibrid48−기준, 문항 bootstrap 95% CI) | 양쪽 통과 응답의 median latency 비율 |
|---|---:|---:|---:|---:|---:|

품질 실행의 두 서빙 구성은 동일하지 않습니다. 기준 실행은 MTP2 / `max_num_seqs=4`, hibrid48은 MTP5 / `max_num_seqs=64`였으며 checkpoint revision과 parser 설정도 다릅니다. 따라서 이 결과는 전체 배포 구성 비교이며 양자화나 checkpoint만의 효과를 분리하지 않습니다. 코딩 차이의 bootstrap 구간은 0을 포함하고, 장문 표본은 8개 문항뿐이므로 일반적인 우열이나 동등성을 입증하지 않습니다.

짧은 Coding에서 기준 실행은 60회 중 19회, hibrid48은 24회가 출력 한도에 걸렸습니다. 장문 요청은 양쪽 모두 24/24회 API 요청이 완료됐고, 준비된 8개 입력의 tokenizer ID 검증도 일치했습니다. 따라서 hibrid48 장문 실패는 요청 전송 장애가 아니라 답변 채점 결과입니다.

## 16K Coding 보충 실행

출력 한도를 16,384 토큰으로 늘린 별도 실행에서 hibrid48은 60회 중 47회 통과, 12회 출력 잘림, 1회 비잘림 품질 실패였습니다. NVIDIA NVFP4 기준 실행의 대응 16K 측정은 완료되지 않아 이 결과는 paired 비교가 아닙니다. 기존 8K 결과는 유지했습니다.

## 이전 처리량 측정

아래 값은 고정된 2,048 출력 토큰 fixture를 사용한 집계 처리량입니다. 표의 `기준 → hibrid48`에서 기준 처리량은 MTP3 / server cap 8, hibrid48은 MTP5 / server cap 64 설정에서 얻었습니다. 서빙 설정이 달라 단일 설정의 양자화 성능 비교로 해석하면 안 됩니다.

### 출력 처리량 (aggregate tok/s)

| Korean prose | 24.63 → 46.98 | 39.90 → 73.64 | 66.59 → 109.58 | 100.55 → 163.26 |

코딩 처리량은 코드 정확도가 아니라 reasoning 토큰 생성률입니다. GPU tok/J는 두 GPU 전력만 적분했고 CPU·시스템 전력과 idle draw를 제외했습니다. 짧고 반복적인 fixture에서 얻은 값이므로 실제 업무의 토큰 처리량이나 에너지 사용량으로 일반화하지 마십시오.

## 해석 및 재현 정보

- 이 Core60은 자체 작성한 합성 회귀 세트입니다. 공식 벤치마크 점수나 contamination-free 평가가 아닙니다.
- 통과율은 전체 평균보다 문항별 회귀와 실패 유형을 확인하는 진단값입니다. 작은 문항 수에서는 한 문항이 큰 비율 차이를 만듭니다.
- Qwen 측정의 기록된 GPU cap 값과 실제 활성 상태에 대한 주의사항은 [README의 GPU 클럭 설명](../../README.md#gpu-클럭과-2000-mhz-설정-기록)에 있습니다. 2,000 MHz metadata를 실행 중 활성 clock lock으로 간주하지 않습니다.
- 공개본에는 집계 보고서만 포함하고, 원시 모델 응답 및 endpoint별 실행 산출물은 제외했습니다.
